02 — Estructura de datos

El corazón del programa:
el diccionario

Todo el sistema vive en una sola variable: un diccionario. Piénsalo como un archivero donde cada cajón tiene un número, y dentro hay la ficha completa del paciente.

🗄️
Analogía: Imagina un archivero físico. Cada cajón tiene un número (la clave). Dentro del cajón hay una tarjeta con: si el paciente sigue activo, su nombre, su especie y su edad.
True = activo
False = eliminado
Texto (nombre/especie)
Número (edad)
Clave única

La CLAVE

Es el número al inicio (1, 2, 3…). Es única — nunca se repite, ni siquiera si reinicias el programa. La genera automáticamente la función generar_clave() sumando 1 al número más alto que ya existe.

La LISTA interna

Cada cajón contiene una lista de 4 cosas en orden fijo:
[0] Estado (True/False)
[1] Nombre
[2] Especie
[3] Edad

04 — Funciones importantes

Las piezas del rompecabezas

Cada función tiene una tarea específica. Haz clic en cada tarjeta para ver más detalles.

💾 preservar(estado, ruta)

Guarda todo el catálogo en un archivo CSV cuando el usuario decide salir. Sin esta función, los datos se perderían al cerrar el programa.

# Abre el archivo y escribe fila por fila
for clave, datos in estado.items():
    writer.writerow([clave, *datos])

El *datos "desempaca" la lista para escribirla como columnas separadas.

📂 recuperacion(estado, ruta)

Al iniciar el programa, busca el archivo CSV guardado anteriormente y lo carga en memoria. Si no existe, simplemente empieza vacío.

try:
    # Lee el CSV y reconstruye el diccionario
    for id_, existe, nombre, especie, edad in reader:
        estado[int(id_)] = [existe == 'True', ...]
except FileNotFoundError:
    pass # No hay archivo, comenzamos vacíos
🔍 buscar_paciente(catalogo, clave)

Busca un paciente por su número de clave. Si no existe o está eliminado (y no se permite ver eliminados), avisa al usuario y devuelve None.

# Si el paciente existe pero está eliminado y
# no pedimos incluir eliminados → error
if not incluir_eliminados and not paciente[0]:
    raise ValueError()
🔢 generar_clave(catalogo)

Genera automáticamente el siguiente número de clave disponible. Siempre toma el número más alto que existe y le suma 1, garantizando que nunca se repita.

return max(catalogo.keys(), default=0) + 1

# Si el catálogo tiene claves 1, 2, 5 → devuelve 6
# Si está vacío (default=0) → devuelve 1
✏️ modificar_paciente(catalogo)

Permite editar los datos de un paciente activo. Muestra cada campo y permite presionar ENTER para conservarlo sin cambios. Pide confirmación antes de aplicar.

# Crea una COPIA para no modificar el original
copia = datos.copy()
# Si el usuario cancela, los datos originales
# siguen intactos en el diccionario
🗑️ eliminar_paciente(catalogo)

Marca al paciente como inactivo cambiando el primer valor de True a False. El paciente sigue existiendo en el diccionario, simplemente "desaparece" de la vista normal.

# Solo cambia el estado, NO borra el registro
catalogo[clave][0] = False
♻️ recuperar_paciente(catalogo)

Lista todos los pacientes eliminados (con False) y permite reactivar uno, cambiando su estado de False a True. El paciente vuelve a aparecer normalmente.

# Muestra solo los eliminados
for clave, datos in catalogo.items():
    if not datos[0]: # Si está inactivo
        print(clave, datos[1])

# Para recuperar:
catalogo[clave][0] = True
📋 reportar_pacientes(catalogo)

Muestra en pantalla una tabla ordenada con todos los pacientes activos. Solo incluye los que tienen True, ignorando los eliminados.

# Filtra solo los activos
activos = [(k, v) for k, v in catalogo.items() if v[0]]

# Imprime en formato de tabla
05 — Eliminación lógica

No borramos, marcamos

Esta es una decisión de diseño muy importante. Cuando "eliminamos" un paciente, no lo borramos realmente. Solo cambiamos un valor de True a False. Esto permite recuperarlo después.

📦
Analogía: Es como tachar un nombre en una lista de papel con lápiz en lugar de borrar la hoja. La información sigue ahí, puedes leerla, pero el sistema la trata como "no existe". Y si quieres, puedes borrar el tachado y el nombre vuelve a estar activo.

Prueba los botones para ver cómo cambia visualmente el estado del paciente:

1 ✓ ACTIVO "FIRULAIS" "PERRO" 5 años
2 ✓ ACTIVO "MICHI" "GATO" 2 años
# Antes de eliminar:
catalogo[1] = [True, "FIRULAIS", "PERRO", 5]

# Después de "eliminar":
catalogo[1] = [False, "FIRULAIS", "PERRO", 5]
# ↑ Solo cambió esto. El resto sigue igual.
06 — Archivos CSV

Cómo se guarda la información

Un CSV es un archivo de texto donde los datos se separan por comas. Es como una hoja de cálculo muy simple. Lo usamos para que el catálogo sobreviva aunque cierres el programa.

07 — Validaciones

El filtro de calidad de datos

Antes de guardar cualquier dato, el sistema verifica que sea correcto. Hay tres funciones clave para esto.

validar_cadena()

Verifica que el texto no esté vacío ni sea solo espacios. Rechaza: "" o " "

validar_numero()

Verifica que sea un número entero. Rechaza: "abc", "3.5", "-1"

solicitar_con_validacion()

Combina las dos anteriores. Si el dato falla, vuelve a preguntar automáticamente hasta recibir algo válido.

09 — Requerimientos del PIA

Cómo cumple el código cada requisito

El PIA pedía funcionalidades específicas. Aquí verás cómo cada una está cubierta en el código.

✓ Requerimiento Cómo lo cumple Función
✓ Clave única que no se repite entre ejecuciones Toma el máximo del diccionario y suma 1. Gracias al CSV, recuerda las claves anteriores generar_clave()
✓ Nombre y especie no vacíos ni solo espacios Valida con strip() antes de aceptar el dato validar_cadena()
✓ Edad como número entero positivo Usa isnumeric() que solo acepta dígitos positivos validar_numero()
✓ Agregar paciente Pide datos, genera clave automática, inserta en diccionario crear_paciente()
✓ Editar paciente con confirmación Trabaja en copia separada, aplica solo si el usuario confirma modificar_paciente()
✓ Eliminación lógica (no física) Solo cambia datos[0] de True a False, el registro persiste eliminar_paciente()
✓ Recuperar pacientes eliminados Lista todos con False y permite reactivar uno recuperar_paciente()
✓ Reporte tabular de pacientes activos Filtra solo los que tienen True e imprime tabla formateada reportar_pacientes()
✓ Guardar y recuperar con CSV Al salir guarda, al iniciar carga. Si no hay archivo, empieza vacío preservar() recuperacion()
✓ Validación centralizada sin duplicar código Una sola función reutilizable que recibe el validador como parámetro solicitar_con_validacion()
✓ Datos en mayúsculas El sistema guarda todo en uppercase para consistencia pedir_datos_paciente()
✓ Punto de entrada main() La función main() controla el inicio y el ciclo del programa main()
✓ Menú con opciones inválidas controladas Usa match/case y avisa si la opción no es válida menu()
