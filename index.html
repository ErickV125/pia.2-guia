La CLAVE

Es el número al inicio (1, 2, 3…). Es única — nunca se repite, ni siquiera si reinicias el programa. La genera automáticamente la función generar_clave() sumando 1 al número más alto que ya existe.

La LISTA interna

Cada cajón contiene una lista de 4 cosas en orden fijo:
[0] Estado (True/False)
[1] Nombre
[2] Especie
[3] Edad

04 — Funciones importantes

Las piezas del rompecabezas

Cada función tiene una tarea específica. Haz clic en cada tarjeta para ver más detalles.

💾 preservar(estado, ruta)

Guarda todo el catálogo en un archivo CSV cuando el usuario decide salir. Sin esta función, los datos se perderían al cerrar el programa.

# Abre el archivo y escribe fila por fila
for clave, datos in estado.items():
    writer.writerow([clave, *datos])

El *datos "desempaca" la lista para escribirla como columnas separadas.

📂 recuperacion(estado, ruta)

Al iniciar el programa, busca el archivo CSV guardado anteriormente y lo carga en memoria. Si no existe, simplemente empieza vacío.

try:
    # Lee el CSV y reconstruye el diccionario
    for id_, existe, nombre, especie, edad in reader:
        estado[int(id_)] = [existe == 'True', ...]
except FileNotFoundError:
    pass # No hay archivo, comenzamos vacíos
🔍 buscar_paciente(catalogo, clave)

Busca un paciente por su número de clave. Si no existe o está eliminado (y no se permite ver eliminados), avisa al usuario y devuelve None.

# Si el paciente existe pero está eliminado y
# no pedimos incluir eliminados → error
if not incluir_eliminados and not paciente[0]:
    raise ValueError()
🔢 generar_clave(catalogo)

Genera automáticamente el siguiente número de clave disponible. Siempre toma el número más alto que existe y le suma 1, garantizando que nunca se repita.

return max(catalogo.keys(), default=0) + 1

# Si el catálogo tiene claves 1, 2, 5 → devuelve 6
# Si está vacío (default=0) → devuelve 1
✏️ modificar_paciente(catalogo)

Permite editar los datos de un paciente activo. Muestra cada campo y permite presionar ENTER para conservarlo sin cambios. Pide confirmación antes de aplicar.

# Crea una COPIA para no modificar el original
copia = datos.copy()
# Si el usuario cancela, los datos originales
# siguen intactos en el diccionario
🗑️ eliminar_paciente(catalogo)

Marca al paciente como inactivo cambiando el primer valor de True a False. El paciente sigue existiendo en el diccionario, simplemente "desaparece" de la vista normal.

# Solo cambia el estado, NO borra el registro
catalogo[clave][0] = False
♻️ recuperar_paciente(catalogo)

Lista todos los pacientes eliminados (con False) y permite reactivar uno, cambiando su estado de False a True. El paciente vuelve a aparecer normalmente.

# Muestra solo los eliminados
for clave, datos in catalogo.items():
    if not datos[0]: # Si está inactivo
        print(clave, datos[1])

# Para recuperar:
catalogo[clave][0] = True
📋 reportar_pacientes(catalogo)

Muestra en pantalla una tabla ordenada con todos los pacientes activos. Solo incluye los que tienen True, ignorando los eliminados.

# Filtra solo los activos
activos = [(k, v) for k, v in catalogo.items() if v[0]]

# Imprime en formato de tabla
05 — Eliminación lógica

No borramos, marcamos

Esta es una decisión de diseño muy importante. Cuando "eliminamos" un paciente, no lo borramos realmente. Solo cambiamos un valor de True a False. Esto permite recuperarlo después.

📦
Analogía: Es como tachar un nombre en una lista de papel con lápiz en lugar de borrar la hoja. La información sigue ahí, puedes leerla, pero el sistema la trata como "no existe". Y si quieres, puedes borrar el tachado y el nombre vuelve a estar activo.

Prueba los botones para ver cómo cambia visualmente el estado del paciente:

1 ✓ ACTIVO "FIRULAIS" "PERRO" 5 años
2 ✓ ACTIVO "MICHI" "GATO" 2 años
# Antes de eliminar:
catalogo[1] = [True, "FIRULAIS", "PERRO", 5]

# Después de "eliminar":
catalogo[1] = [False, "FIRULAIS", "PERRO", 5]
# ↑ Solo cambió esto. El resto sigue igual.

07 — Validaciones

Antes de guardar cualquier dato, el sistema verifica que sea correcto. Hay tres funciones clave para esto.

validar_cadena()

Verifica que el texto no esté vacío ni sea solo espacios. Rechaza: "" o " "

validar_numero()

Verifica que sea un número entero. Rechaza: "abc", "3.5", "-1"

solicitar_con_validacion()

Combina las dos anteriores. Si el dato falla, vuelve a preguntar automáticamente hasta recibir algo válido.

¿Qué es el ciclo while True?

Normalmente un programa hace sus cosas y termina. Pero nosotros necesitamos que el sistema siga funcionando hasta que el usuario decida salir. La instrucción while True crea un bucle eterno. El programa repite: "muestra el menú → espera la opción → ejecuta la función → vuelve al menú" indefinidamente.

# Así funciona el ciclo infinito: while True: # ← siempre verdadero = nunca para menu(catalogo, ruta_csv) # ← muestra menú y procesa opción # ↑ cuando menu() termina, vuelve aquí y repite # Solo sale si dentro de menu() se llama exit()
NÚCLEO 02

Por qué elegimos un diccionario

Podríamos haber guardado los pacientes de muchas formas. Elegimos el diccionario por razones muy concretas. Compara:

❌ Variables separadas
nombre1 = "FIRULAIS"
especie1 = "PERRO"
nombre2 = "MICHI"
especie2 = "GATO"
# ¿Y si hay 500 pacientes?

Imposible de manejar. Cada nuevo paciente requiere nuevas variables. Sin estructura.

❌ Lista de listas
pacientes = [
  ["FIRULAIS","PERRO",5],
  ["MICHI","GATO",2]
]
# Para buscar clave 47:
# hay que recorrer TODA la lista

Lento para buscar. No hay acceso directo. La clave 47 requiere revisar 1 a 46 primero.

✅ Diccionario
catalogo = {
  1: [True,"FIRULAIS","PERRO",5],
  47: [True,"MICHI","GATO",2]
}
# Para buscar clave 47:
catalogo[47] # ← directo, instantáneo

Acceso instantáneo por clave. Sin importar cuántos pacientes haya, siempre es igual de rápido.

🗄️
Analogía del archivero: Imagina buscar un expediente. Con variables sería revisar hojas sueltas tiradas en el suelo. Con lista sería revisar uno por uno desde el primer cajón. Con diccionario es como tener cajones numerados: vas directo al cajón 47 sin abrir los demás.
La magia de catalogo[clave]

Cuando escribimos catalogo[47], Python va directamente al espacio de memoria donde está guardado el paciente 47. No revisa el 1, el 2, el 3... Va directamente. Esto se llama acceso O(1) — tiempo constante, siempre igual de rápido.

🗂️ 1 → FIRULAIS
🗂️ 2 → MICHI
🗂️ 3 → ROCCO
🗂️ 47 → LUNA ← acceso directo
🗂️ 48 → MAX
catalogo[47] ──→

NÚCLEO 05

Eliminación lógica: no borrar, marcar

Esta es una decisión de arquitectura con consecuencias importantes. Comparemos las dos opciones:

❌ Eliminación física

Se borra el registro completamente del diccionario.

1 → [True, "FIRULAIS", "PERRO", 5]
2 → [True, "MICHI", "GATO", 2]
3 → [True, "ROCCO", "CONEJO", 3]
🚫 No se puede recuperar
🚫 La clave 2 queda huérfana para siempre
🚫 Si fue error del usuario, se perdió todo
✅ Eliminación lógica

Solo se cambia el estado a False. El registro permanece.

1 → [True, "FIRULAIS", "PERRO", 5]
2 → [True, "MICHI", "GATO", 2]
3 → [True, "ROCCO", "CONEJO", 3]
✅ Recuperable en cualquier momento
✅ Historial completo preservado
✅ El CSV guarda activos e inactivos
Cómo el sistema filtra sin borrar

Las funciones como reportar_pacientes() no ven a los inactivos porque filtran por datos[0]:

# Solo incluye pacientes donde datos[0] == True activos = [(k, v) for k, v in catalogo.items() if v[0]] # buscar_paciente() también filtra: if not incluir_eliminados and not paciente[0]: raise ValueError() # ← paciente inactivo, no se muestra
NÚCLEO 06

Validaciones centralizadas: no repetir código

Este es un principio fundamental del buen código: si haces lo mismo en varios lugares, extráelo a una sola función. Llámala cada vez que la necesites.

🏭
Analogía: En una fábrica, no construyes una máquina diferente para cada tornillo que quieres apretar. Construyes una llave y la usas en todos lados. Las funciones de validación son esa llave reutilizable.
❌ Sin centralizar — código repetido
# En crear_paciente(): while True: nombre = input("Nombre: ") if nombre.strip(): break print("Error") # En modificar_paciente(): while True: nombre = input("Nombre: ") if nombre.strip(): break print("Error") # ← mismo código 3, 4, 5 veces...
Si encuentras un bug, tienes que corregirlo en 5 lugares distintos. Fácil olvidar uno.
✅ Centralizado — una sola función
# Una sola vez, en solicitar_con_validacion(): def solicitar_con_validacion(validar, mensaje): while True: try: return validar(input(mensaje)) except ValueError as e: print(f'Error: {e}') # En cualquier función, solo llamas: solicitar_con_validacion(validar_cadena, "Nombre: ") solicitar_con_validacion(validar_numero, "Edad: ")
Un solo lugar para corregir. Funciona igual en todos lados. Código limpio.
El patrón: pasar funciones como parámetros

Un detalle elegante: solicitar_con_validacion recibe qué función usar para validar como parámetro. Esto la hace flexible — puede validar cualquier cosa:

# Pasamos validar_cadena como argumento → valida texto solicitar_con_validacion(validar_cadena, "Ingrese el nombre: ") # Pasamos validar_numero como argumento → valida números solicitar_con_validacion(validar_numero, "Ingrese la edad: ") # La función no sabe qué valida; solo sabe cómo preguntar # y repetir si falla. Eso la hace reutilizable.

NÚCLEO 08

La filosofía detrás del diseño

Cada decisión técnica tiene una razón. No escribimos el código "porque sí". Aquí están los principios que guiaron el diseño:

🎯
Separación de responsabilidades

Cada función hace una sola cosa. validar_cadena() solo valida, no pregunta. pedir_datos_paciente() solo pide, no guarda. generar_clave() solo genera la clave, no crea al paciente. Así cada pieza es fácil de entender y de reparar.

♻️
Reutilización

buscar_paciente() es usada por modificar, eliminar y recuperar. solicitar_con_validacion() es usada por cualquier función que pida datos. Escribir código una vez y reutilizarlo muchas veces reduce errores y facilita el mantenimiento.

🛡️
Defensa de los datos

Las validaciones impiden que entren datos basura. La eliminación lógica impide perder información accidentalmente. La copia en modificar_paciente() impide modificaciones sin confirmación. El sistema protege los datos del usuario incluso de sus propios errores.

💾
Persistencia garantizada

Los datos sobreviven al cierre del programa. El CSV guarda incluso los registros "eliminados" para que puedan recuperarse en la próxima sesión. Nada se pierde mientras el usuario no lo decida explícitamente.

📖
Claridad sobre brevedad

Los nombres de las funciones son largos pero descriptivos: recuperar_paciente(), solicitar_con_validacion(). Se eligieron nombres que explican su propósito sin necesitar comentarios, porque el código que se lee bien, se mantiene bien.

🏗️
Estructura predecible

Siempre: el índice [0] es el estado, [1] es el nombre, [2] es la especie, [3] es la edad. En todo el programa. Esto significa que cualquier función puede trabajar con cualquier paciente sin sorpresas ni inconsistencias.
